# fenicsx-navier-stokes

Stabilized incompressible Navier–Stokes solvers in [FEniCSx](https://fenicsproject.org) for vascular haemodynamics: patient-specific aortas with Windkessel outlets, a 3D vessel segment, and the DFG flow-around-a-cylinder benchmark.

```python
from fenicsx_navier_stokes import ParameterHandler, PicardNSProblem, Windkessel

pars = ParameterHandler("examples/aorta/Ao11mmrest.yaml")
problem = PicardNSProblem(parameters=pars, mesh=mesh, boundaries=facet_tags,
                          windkessels=windkessels, element="P1-P1")
problem.solve(xdmf_path="output/aorta.xdmf", store_after=0, store_every=10)
```

## The scheme

Momentum and mass are solved together as a single saddle-point system per nonlinear iteration — no projection or fractional-step splitting.

| | |
|---|---|
| Time stepping | BDF2, semi-implicit |
| Nonlinearity | Picard (Oseen) linearization, iterated to a relative velocity tolerance |
| Elements | equal-order **P1-P1** (stabilized) or inf-sup stable **P2-P1** |
| Stabilization | residual-based SUPG + PSPG + grad-div |
| Linear algebra | 2×2 PETSc `MatNest`; MUMPS LU, or FGMRES + Schur fieldsplit (`selfp`) + BoomerAMG |
| Outlets | three-element RCR Windkessel, plus optional backflow stabilization |

The stabilization parameter is

$$\tau_M = \Bigl[(\sigma/\Delta t)^2 + (|u|/h)^2 + C_k\,(\mu/\rho h^2)^2\Bigr]^{-1/2}, \qquad C_k = 60\cdot 2^{k-2},$$

and every stabilization term weights the strong residual, which vanishes on the exact solution — so the scheme is consistent and does not degrade the formal order of accuracy. Measured on a manufactured solution at $\rho = 1.06$: **L²(u) rate 2.00, H¹(u) rate 1.06**.

Only the blocks that depend on the Picard iterate are re-assembled each iteration; the BDF2 mass-plus-viscous block and the two divergence blocks are assembled once and added back with `axpy`.

## Running with Docker

`dolfinx`, PETSc, MPI and `basix` cannot be installed from PyPI, so everything runs inside a pinned container. The image supplies the *environment* only: the project source is not baked in, it is mounted at `/work` when the container starts, so edits on the host take effect immediately and the image never carries a stale copy.

### Build the image

```bash
make image
# equivalently:
docker build -t fenicsx-ns-dev -f docker/Dockerfile .
```

The base tag is pinned deliberately. The solver uses the `kind="nest"` block-assembly API and `V.element.interpolation_points` as a *property*, neither of which exists in the 0.8 series still tagged `dolfinx/dolfinx:stable` — the code will not even import there. Python dependencies live in `docker/requirements.txt`.

### Run things

```bash
make shell        # interactive shell, repo mounted at /work
make test         # fast test suite (about a minute)
make test-slow    # convergence studies and benchmarks
make test-mpi     # two-rank smoke (the image ships MPICH, so no extra mpirun flags)
make lint         # what CI enforces
make examples     # every example at smoke size
make help         # all targets
```

Any of these is just a container invocation underneath:

```bash
docker run --rm -u "$(id -u):$(id -g)" -v "$PWD":/work -w /work fenicsx-ns-dev \
    python3 -m pytest tests -q
```

### Always pass `-u`

```bash
-u "$(id -u):$(id -g)"
```

Without it the container runs as root, and everything it writes into the mounted tree — simulation output, `.pytest_cache`, the built docs — ends up owned by root and cannot be deleted by your normal user afterwards. The Makefile passes it by default; use `make test USER_FLAG=` to run as root deliberately. If you already have root-owned leftovers:

```bash
make fix-permissions
```

The image sets `PYTHONDONTWRITEBYTECODE=1` for the same reason, and points the FFCx, matplotlib and gmsh caches at `/tmp` so it works under any UID.

### Run a simulation

```bash
# one cardiac cycle of the aorta on 8 ranks
docker run --rm -u "$(id -u):$(id -g)" -v "$PWD":/work -w /work fenicsx-ns-dev \
    mpirun -n 8 python3 examples/aorta/run.py --config examples/aorta/Ao11mmrest.yaml
```

`--config` is the only command-line argument the examples take; every parameter is set in the YAML file. The `Run:` section holds the output directory, the element pair, how many steps to take and which of them are written to XDMF. Setting `Run.StoreAfter` enables field output; leaving it `null` writes only the diagnostics CSV. Results land in `output/` on the host, which is gitignored.

### Data

The aorta meshes are large binaries (~28 MB) and are **not** kept in the repository, since git would retain every version of them forever. Obtain them separately and place them under `data/aorta/<case>/`; see [`data/aorta/README.md`](data/aorta/README.md) for the expected layout.

Everything else works without them: the cylinder and tube meshes are generated by gmsh on the fly, and the inflow waveforms in `data/inflow/` are small text files kept under version control. With the meshes absent, the aorta example cannot run and one mesh-consistency test skips; nothing else is affected.

### Without Docker

If you already have dolfinx 0.10 available some other way (conda, Spack, a system build), the package needs only `numpy`, `pyyaml` and `pint`, plus `gmsh` for the geometry generators and `pytest` and `scipy` for the tests:

```bash
pip install -e ".[dev,mesh,plot]"
```

## Examples

```bash
# DFG 2D-3 cylinder benchmark: drag, lift and pressure drop to CSV
python examples/turek/run.py --config examples/turek/turek2d.yaml

# 3D vessel segment with an RCR Windkessel outlet
python examples/tube3d/run.py --config examples/tube3d/tube3d.yaml

# Patient-specific aorta, four Windkessel outlets (hours; use MPI)
mpirun -n 8 python examples/aorta/run.py --config examples/aorta/Ao11mmrest.yaml
```

Each writes a per-step CSV of diagnostics alongside the XDMF fields. Mesh resolution, time step, run length and output paths are all in the `Run:` section of the corresponding YAML file; set `Run.MaxSteps` to a small number for a quick check.

These are shown as bare commands for readability; run them inside the container, either from `make shell` or by prefixing `docker run --rm -u "$(id -u):$(id -g)" -v "$PWD":/work -w /work fenicsx-ns-dev`. `make examples` runs all three at smoke size.

### What each example is for

**`turek`** — verification against published reference values.  Case 2D-3 is the default because it starts from rest, matching the solver's cold BDF2 start.  Reference values (V. John, *IJNMF* **44** (2004) 777–788): $c_{D,\max} = 2.9509$ at $t = 3.936$, $c_{L,\max} = 0.478$ at $t = 5.693$, $\Delta p(8\,\mathrm{s}) = -0.1116$.

Be realistic about cost. A *first-order* Crouzeix–Raviart discretization needed ~785k dofs and $\Delta t = 0.0025$ to reach $c_{D,\max}$ within 0.8 % and $\Delta p$ within 9 %. Stabilized P1-P1 is not better, so matching the published intervals is a multi-million-dof, multi-hour job — not something CI can do. The default mesh is a smoke-test mesh.

**`tube3d`** — analytic verification of the Windkessel coupling. With the shipped parameters ($R_dC = 1/4\pi$) and the $\sin^2(2\pi t)$ waveform, the outlet pressure has the closed form

$$P(t) = R_dQ_0\Bigl[\bigl(\tfrac{R_p}{R_d}+\tfrac12\bigr)\sin^2\tfrac{\tau}{2}
        + \tfrac14\bigl(1 - e^{-\tau} - \sin\tau\bigr)\Bigr],\quad \tau = \frac{t}{R_dC}.$$

Change the parameters and the waveform together or the case stops being a verification.

**`aorta`** — the production case: ~110k nodes, 640k tetrahedra, four RCR outlets, CGS units. It ships *diagnostics*, not assertions — there is no trusted reference solution to regress against. The default is one cardiac cycle (1000 steps); use `Ao11mmrest-12cycles.yaml` when the Windkessel pressures need to reach a periodic state, which takes several cycles. Pressures are reported in mmHg with physiological warnings.

## Tests

Run them with `make test`, `make test-slow` and `make test-mpi` (see [Running with Docker](#running-with-docker)). The suite is layered:

- **`tests/unit/`** — the Windkessel ODE against closed-form solutions; the discrete facet normal; the inlet profile against its modified-Bessel solution; `tau_M` against a hand-computed value; and the assembled block structure (the `axpy` shortcut against a from-scratch assembly, $A_{10} = A_{01}^\mathsf{T}$, the divergence theorem, the BDF2 coefficients).
- **`tests/verification/`** — a uniform-flow patch test and manufactured-solution convergence studies.
- **`tests/benchmarks/`** — DFG and tube cases at CI size, with the full-resolution variants marked `slow`.

Two notes on reading the results. First, the **global** mass balance $\int \nabla\!\cdot u = 0$ holds to round-off *by construction*: testing the continuity row with the constant pressure function annihilates every stabilization term. It confirms the assembly, not the quality of the velocity field — for that, look at `postprocess.divergence_norm`. Second, `pytest` is configured to turn `RuntimeWarning` into an error, which is what keeps a silently-`nan` convergence criterion from coming back.

## Units

The aorta case is CGS throughout: velocity cm/s, viscosity poise, density g/cm³, pressure barye (÷1333.22 for mmHg). The DFG benchmark is non-dimensional. Nothing in the solver assumes a unit system; configurations may optionally carry explicit units (`{value: 0.04, unit: poise}`), resolved by `parameters.magnitude`.

## Layout

```
src/fenicsx_navier_stokes/
  problems.py        BaseProblem, PicardNSProblem — assembly, Picard loop, time loop
  boundaries.py      facet normals, inlet profiles, Windkessel, backflow stabilization
  stabilization.py   tau_M, tau_C and the strong-residual halves
  constitutive.py    eps, Newtonian, PowerLaw
  postprocess.py     flow rate, mass balance, drag/lift, point evaluation
  parameters.py      YAML + optional pint units, dot-notation access
  helpers.py         inflow waveforms, L2 projection
examples/{aorta,turek,tube3d}/   mesh.py (generated geometries), run.py, *.yaml
```
