# Aorta meshes

The patient-specific aorta meshes are large binaries — roughly 28 MB for the three cases, about 110000 nodes and 640000 tetrahedra each — and are deliberately **not** kept in this repository. Git stores every version of a binary forever, so committing them would permanently inflate every clone.

Obtain them separately and place them here. The layout the configurations expect is:

```
data/aorta/
├── 9mmrest/
│   ├── mesh_volume.xdmf    mesh_volume.h5
│   └── mesh_surface.xdmf   mesh_surface.h5
├── 11mmrest/   (same four files)
└── 13mmrest/   (same four files)
```

Each case needs both pairs: the volume file carries the tetrahedra and their region markers, the surface file the boundary facet markers. Paths are set by `MeshFile` and `BoundariesFile` in the corresponding `examples/aorta/Ao*.yaml`.

Facet tags differ between cases and are recorded in each configuration — `WallID` is 4 for the 9 mm and 11 mm meshes but 1 for 13 mm. Pointing a configuration at the wrong mesh yields no boundary conditions at all rather than an error, so the solver validates the tags when the problem is built and refuses to run on a mismatch.

Without these files the aorta example cannot run, and `tests/unit/test_meshdata.py::test_aorta_configs_match_their_meshes` skips. Everything else in the repository works: the DFG cylinder and 3D tube meshes are generated by gmsh on the fly, and the inflow waveforms in `data/inflow/` are small text files kept under version control.
