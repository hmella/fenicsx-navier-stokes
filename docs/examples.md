# Examples

Every example takes a single argument, `--config`, and reads every parameter from that YAML file. Mesh resolution, time step, run length, element pair, output directory and which steps are written to XDMF live in its `Run:` section; the nonlinear solver is `Solver.Scheme`. Each writes a per-step CSV of diagnostics next to the XDMF fields.

## Aorta

```bash
mpirun -n 8 python examples/aorta/run.py --config examples/aorta/Ao11mmrest.yaml
```

Patient-specific geometry, four RCR outlets, CGS units (cm/s, poise, g/cm³, barye). Three segmentations ship: 9 mm, 11 mm and 13 mm.

The default is one cardiac cycle — 1000 steps at $\Delta t = 8\times10^{-4}$ s, the time step being the row spacing of the inflow waveform. Use `Ao11mmrest-12cycles.yaml` when the Windkessel pressures need to reach a periodic state, which takes several cycles; expect a multi-hour parallel run.

!!! warning "The wall tag is not the same on every mesh"
    `WallID` is 4 for the 9 mm and 11 mm cases and 1 for 13 mm. That is correct per-mesh
    metadata, but crossing a configuration with the wrong mesh produces *no* boundary
    conditions rather than an error. The solver checks this at construction and refuses.

Diagnostics are reported, not asserted — there is no trusted reference solution. Pressures are converted to mmHg with physiological warnings, alongside per-cap flow split, mass defect, divergence norm, Picard counts and per-step wall time. The CSV is flushed every step so a job killed by a scheduler still leaves usable data.

## DFG cylinder (Turek)

```bash
python examples/turek/run.py --config examples/turek/turek2d.yaml
```

Three cases, selected with `Run.Case`: `2d1` (steady, Re 20), `2d2` (periodic, Re 100), `2d3` (ramped, the default — it starts from rest, which matches the solver's cold BDF2 start).

Drag and lift are computed two ways: the reaction-force (variational) method, which is the one to trust, and the surface traction integral as a cross-check. The two differ only through the discrete mass-conservation defect, so the gap between them is itself a diagnostic.

The mesh is generated by `turek_mesh.py` as first-order triangles. Recombining into quadrilaterals or raising the geometry order breaks the P1 stabilization, which assumes an affine simplex.

## 3D tube

```bash
python examples/tube3d/run.py --config examples/tube3d/tube3d.yaml
```

A straight vessel segment with an RCR Windkessel outlet. With the shipped parameters this is an analytic verification case — see [Verification](verification.md). `Run.WallResolution` grades the mesh radially, which any boundary-layer-sensitive study needs.

!!! danger "Do not change the Windkessel parameters alone"
    The closed-form reference holds only because $R_dC = 1/4\pi$ matches the
    $\sin^2(2\pi t)$ waveform. Change one without the other and the case silently stops
    being a verification.
